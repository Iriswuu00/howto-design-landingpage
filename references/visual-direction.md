# 设计方向与页面架构参考

本文件用于把品牌访谈转成可在本地 HTML 中执行的设计系统。它参考上游原版 Skill 的设计翻译逻辑，但不再调用 Stitch。

## 本地设计模型

- **项目**：一个落地页项目，对应一个输出目录。
- **屏幕/页面**：一个版本化 HTML 文件，例如 `desktop-v1.html`。
- **设计系统**：颜色、字体、形状、密度和图像方向，保存在 `DESIGN.md` 和 `color-tokens.json`。
- **生成**：由模型直接编写语义化 HTML/CSS，不经过远程设计服务。
- **版本**：每次重要修改都保存新文件，旧版本保留。
- **素材**：本地图片、Logo、字体和用户提供的文档。

## 字体人格指南

必须同时选择标题字体和正文字体。

### 现代 / 干净的 Sans-Serif

适合：现代、干净、极简、技术、锐利。

| 字体 | 性格 | 适用 |
|---|---|---|
| Plus Jakarta Sans | 几何、友好、可读性强 | 现代 SaaS 的默认选择 |
| DM Sans | 略圆润、温暖现代 | 亲和型 SaaS |
| Geist | 锐利、当代 | 开发者工具 |
| Sora | 几何且有性格 | 创意科技、设计工具 |
| Space Grotesk | 技术、留白感 | 工程工具、数据产品、API |
| IBM Plex Sans | 结构化、权威 | 企业、基础设施 |
| Inter | 中性、通用 | 安全默认值，可能偏普通 |

### 温暖 / 友好 Sans-Serif

适合：温暖、友好、亲切、邀请感。

| 字体 | 性格 | 适用 |
|---|---|---|
| Nunito Sans | 圆润、柔和 | 消费产品、社区平台 |
| Rubik | 略圆、扎实 | 协作工具、社交产品 |
| Lexend | 易读性优先 | 教育、可访问性产品 |
| Manrope | 几何但温暖 | 生活方式产品、团队工具 |

### 专业 / 企业

适合：专业、可信、成熟、可靠。

| 字体 | 性格 | 适用 |
|---|---|---|
| Public Sans | 清晰、公共机构感 | 合规、安全、金融 |
| Source Sans 3 | 干净专业 | 咨询、医疗科技 |
| Work Sans | 稳重通用 | 工具、生产力产品 |
| Hanken Grotesk | 清晰、北欧感 | 设计系统、建筑 |
| Arimo | 熟悉、保守 | 传统 B2B |

### 传统 / 优雅 Serif

适合：优雅、高级、精致、经典。

| 字体 | 性格 | 适用 |
|---|---|---|
| Newsreader | 编辑感、杂志感 | 内容平台、出版工具 |
| Libre Caslon Text | 经典、书卷气 | 写作工具、知识库 |
| EB Garamond | 古典优雅 | 高级服务、高端产品 |
| Literata | 精致、温暖 | 精品 SaaS |
| Source Serif 4 | 温暖、可读 | 专业服务 |
| Domine | 稳重、可读 | 金融、地产 |
| Noto Serif | 全球字符覆盖 | 国际化产品 |

### Display / 标题专用

适合需要强记忆点的标题，但正文应配更中性的字体。

- Epilogue：编辑感、创意机构
- Be Vietnam Pro：独特、消费产品
- Spline Sans：技术、精确
- Montserrat：几何、营销活动
- Metropolis：都市、强品牌

### 推荐组合

| 产品类型 | 标题 | 正文 | 感受 |
|---|---|---|---|
| SaaS / Web App | Sora | DM Sans | 干净、亲和 |
| Dev Tool / CLI / API | Geist | Space Grotesk | 技术、锐利 |
| 开源项目 | Plus Jakarta Sans | Inter | 开放、可读 |

## 色彩策略决策树

| 品牌性格 | 策略 | 理由 | 例子 |
|---|---|---|---|
| 大胆、活力、能量 | 高饱和强调色 | 高对比、动态 | 营销工具、社交产品 |
| 干净、极简、技术 | 中性色 + 单一主色 | 克制、可信 | Dev tools、API |
| 精致、微妙 | 同色系层次 | 细腻的色调变化 | 设计工具、分析平台 |
| 戏剧化、单一焦点 | 单色系 | 单色深度 | 作品集、高级工具 |
| 活泼、表达性、创意 | 多色但受控 | 丰富但有规则 | 消费产品、创意工具 |
| 必须忠实品牌 | 现有品牌色 | 保持识别性 | 已有品牌规范 |
| 自然、有机 | 大地色/内容取色 | 温暖、自然 | 健康、可持续 |
| 俏皮、节庆、多元 | 彩虹色但控制层级 | 强烈多样性 | 创意平台、社区 |
| 清新、彩色、愉快 | 多色但协调 | 友好、轻快 | 教育、社交 |

| 稳定、专业 | `#1E3A5F` | 海军蓝 |
| 能量、紧迫 | `#DC2626` | 红色 |
| 温暖、友好 | `#EA580C` | 橙色 |
| 成长、健康、开源 | `#16A34A` | 绿色 |
| 现代、清新 | `#0D9488` | 青绿色 |
| 创意、高级 | `#7C3AED` | 紫色 |

### 颜色角色

先定义角色，再决定色值：

- Canvas：页面背景
- Surface：卡片、导航、表单
- Ink：主文字
- Muted：辅助文字
- Primary：主 CTA、链接、选中状态
- Accent：品牌识别、小面积强调
- Line：边框和分隔线
- Success / Warning / Error：功能反馈

品牌色适合 Logo 不代表适合大面积背景。必须根据角色重新判断。

## 页面构建模式

### 生成第一版前必须写清楚

```text
项目名称：
一句话定位：
目标用户：
主要 CTA：
品牌形容词：
明暗模式：
主色及颜色角色：
标题字体：
正文字体：
形状语言：
页面模块：
禁止事项：
```

### Hero 设计规则

Hero 至少要回答：

- 这是什么产品
- 为什么值得继续看
- 下一步做什么

推荐结构：

```text
一行主标题
一行副文案
一个主 CTA
一个能看清产品的视觉主体
```

如果产品外观是购买驱动因素：

- 不要让不透明文案面板盖住产品
- 如果使用全屏图，文案通常要更少
- 用渐变、暗角或局部遮罩保证文字可读
- 必须验证遮罩的层级和透明度

### 局部修改模式

| 修改类型 | 指令模式 |
|---|---|
| 布局重排 | 把信任模块移动到功能模块之前 |
| 色彩变化 | 让 Hero 背景更暗，但保持 CTA 对比 |
| 字体层级 | 让主标题更醒目，但不要增加新字体 |
| 内容替换 | 将标题替换为已确认文案 |
| CTA 强化 | 提高主按钮对比度和可见性 |
| 删除元素 | 删除没有证据支持的第三张卡片 |
| 增加板块 | 增加价格或 FAQ，并说明为什么需要 |
| 留白 | 增加模块之间的呼吸感，但不改变信息顺序 |
| 图片构图 | 保持产品完整，调整文字位置而不是裁切主体 |

### 生成约束

- 不写死行业模板。
- 不为了“丰富”而增加无证据内容。
- 不在 Hero 堆叠所有卖点。
- 不使用超过 5–6 个连续信息模块。
- 不把现有品牌资产换成伪造近似物。
- 不在没有数据时编造社会证明。

## 落地页板块分类

### 标准板块与推荐顺序

| # | 板块 | 目的 | 何时使用 |
|---|---|---|---|
| 1 | Hero | 标题、副文案、主 CTA、产品视觉 | 始终 |
| 2 | 社会证明条 | 客户、媒体、奖项、已验证指标 | 有可信证据时 |
| 3 | 问题/解决 | 用户痛点与解决方式 | 痛点明确时 |
| 4 | 功能/利益点 | 3–4 个真实差异点 | 功能多且有价值时 |
| 5 | 使用方式 | 三步流程或工作原理 | 产品需要解释时 |
| 6 | 产品演示/代码 | Demo、截图、代码片段 | 软件或 API |
| 7 | 集成 | 生态兼容性 | 依赖生态时 |
| 8 | 用户评价 | 第三方背书 | 有真实授权评价时 |
| 9 | 价格 | 价格或套餐 | 价格是决策因素时 |
| 10 | FAQ | 处理购买疑问 | 问题可预测时 |
| 11 | 关于/故事 | 团队、公司或 IP 背景 | 品牌信任需要时 |
| 12 | 最终 CTA | 重复主要行动 | 通常需要 |
| 13 | 页脚 | 联系、社交、法律、版权 | 始终 |

### 按产品类型选择

| 产品类型 | 推荐板块 |
|---|---|
| SaaS / Web App | Hero、信任、功能、使用方式、价格、评价、最终 CTA、页脚 |
| Dev Tool / CLI | Hero、代码/Demo、功能、使用方式、集成、最终 CTA、页脚 |
| API / SDK | Hero、代码/Demo、功能、集成、价格、FAQ、最终 CTA、页脚 |
| 开源项目 | Hero、代码/Demo、功能、社会证明、关于、最终 CTA、页脚 |
| 开发者作品集 | Hero、项目、评价、关于、最终 CTA、页脚 |
| 独立产品 | Hero、问题/解决、功能、价格、FAQ、最终 CTA、页脚 |
| 消费硬件 | Hero、产品故事、功能、生活场景、规格、信任、FAQ、最终 CTA、页脚 |
| B2B 服务 | Hero、问题/解决、案例、流程、信任、联系、页脚 |
| 多产品微站 | Hero、产品总览、各产品详情、共享信任、共享 CTA、页脚 |

## 圆角

| 类型 | 半径 | 感受 | 典型用途 |
|---|---|---|---|
| 锐利 | 4px | 精确、技术 | 金融、企业、开发者工具 |
| 平衡 | 8px | 现代、默认 | 大多数产品 |
| 柔和 | 12–16px | 友好、消费 | 消费 App、SaaS |
| 全圆角 | Pill | 活泼、行动导向 | 按钮、标签、消费品 |

## 设计系统落地顺序

1. 读取访谈摘要。
2. 定义品牌方向。
3. 选择颜色角色和排版策略。
4. 选择标题/正文字体。
5. 选择形状和密度。
6. 写 `design/DESIGN.md`。
7. 写 `design/color-tokens.json`。
8. 确定板块列表和顺序。
9. 写入 `.howto-design-landingpage/metadata.json`。
10. 进入本地 HTML 实现。
