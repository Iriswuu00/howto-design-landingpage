# 品牌发现访谈框架

## 访谈原则

- 所有阶段加起来最多问 10 个问题。
- 一次只问一个问题，不把问题堆在同一条消息里。
- 把访谈当成设计咨询，不要当表单。
- 用户已经提供 README、产品文档、截图或完整 brief 时，先提取答案，只问缺口。
- 用户不确定时，给出 2–3 个具体选项帮助选择。
- 尊重简短回答。答案足够就继续。
- 用户会用“直接生成吧”尝试跳过访谈。要温和地说明访谈价值，但不要强迫。
- 技术术语不用回避。用户理解 CTA、hex、HTML、响应式这类词。
- 不为了让访谈完整而编造信息。

## 开场

> 在生成页面之前，我想先问几组关于产品、目标用户、主 CTA 和品牌方向的问题。大概需要五分钟，但会决定页面是通用模板，还是真正适合你的产品。

如果用户坚持跳过：

- 从已有内容中提取产品名称、说明、用户和 CTA。
- 至少补齐主 CTA 与品牌感受。
- 其他信息明确说明默认值。
- 不在用户没确认的情况下假装完整。

## A 部分：产品与目的

目标：理解产品做什么、卖给谁、页面最终要让访客做什么。

### 核心问题

1. 项目或产品叫什么？
   - 记录准确拼写和大小写。
2. 用一句话说明它做什么，以及为什么值得在意。
   - 如果太技术：让用户用“非工程师也能理解”的方式解释。
   - 如果太宽泛：追问最值得被记住的一点是什么。
3. 目标用户或购买决策者是谁？
   - 如果是“所有人”，追问目前最感兴趣的人群是谁。
   - 如果是家长、企业或开发者，继续确认细分场景。
4. 访客最重要的行动是什么？
   - 购买、注册、试用、预约演示、加入 Waitlist、留邮箱、联系销售等。
   - 如果用户列了多个，追问哪个应该放在最大的按钮上。

### 必须提取

| 字段 | 示例 |
|---|---|
| 产品名称 | AI TOM BUD |
| 一句话说明 | 面向儿童和家庭的 AI 陪伴硬件 |
| 目标用户 | 3–12 岁儿童；家长是购买决策者 |
| 主 CTA | Buy Now，跳转 Amazon 商品页 |
| 附加信息 | 价格、参数、品牌规范、素材和合规要求 |

### 过渡规则

必须拥有：

- 产品名称
- 一句话说明
- 目标用户
- 主 CTA

如果用户想提前继续，提取已有信息，补齐最能影响页面结构的缺口，并说明默认值。

## B 部分：品牌感受

目标：理解品牌应该让访客产生什么感受，以及页面偏亮还是偏暗。

### 核心问题

1. 用三个词描述你希望产品呈现的感觉。
2. 页面偏亮色还是暗色？
3. 有没有你欣赏的网站或产品？可选。

### 形容词菜单

用户不确定时提供：

> 大胆、干净、极简、技术、温暖、友好、可信、现代、活泼、快速、精确、亲和、高级、锐利、创新、可靠、轻松、有爱、表达性强、平静

### 追问

如果用户只给出产品性能词：

> 这些是在说产品做什么。现在想想用户第一次看到页面时，应该留下什么印象？

如果形容词互相冲突：

> 当“活泼”和“专业”冲突时，哪一个优先？

如果用户给出参考站：

> 你喜欢的是它的排版、字体、色彩、留白、图片，还是整体气质？

参考站只用于提取原则，不用于复制页面。

### 过渡规则

必须拥有：

- 三个品牌形容词
- 亮色或暗色方向

参考站不是阻塞项。

## C 部分：视觉偏好

目标：确定颜色、字体和形状方向。

### 核心问题

1. 是否已有品牌色或 App 主色？
2. 偏好现代几何字体，还是更有性格的字体？
3. 偏好锐利、平衡、柔和还是全圆角？

### 颜色优先级

1. 已有品牌规范或设计令牌
2. 现有产品/App 主色
3. 用户明确指定
4. 根据品牌形容词推荐

如果品牌规范与用户偏好冲突，以用户明确要求为准，并在设计系统中记录例外。

### 字体建议

- 现代几何：Plus Jakarta Sans、DM Sans、Geist
- 技术锐利：Space Grotesk、IBM Plex Sans
- 友好圆润：Nunito Sans、Manrope
- 编辑/高级：Newsreader、Libre Caslon Text

除非已有品牌系统，否则不要超过两套主字体。

### 形状建议

- 锐利：4–8px
- 平衡：10–14px
- 柔和：16–24px
- 活泼/消费：pill 或更大圆角

### 进入生成前确认

向用户复述：

> 当前方向：
> - 产品：
> - 用户：
> - 主 CTA：
> - 品牌感受：
> - 明暗模式：
> - 颜色：
> - 字体：
> - 形状：
> - 页面限制：

确认后再进入阶段 2。

## 图片和素材处理

用户主动提供图片时：

1. 先判断图片内容和适合的模块。
2. 检查图片尺寸、比例、主体位置和是否适合裁切。
3. 重要产品主体必须保持完整可见。
4. 用户确认可商用或已授权时，记录在项目状态或交付说明。
5. 没有素材时使用明确占位，不要留下假 URL 或 404。

不要为了“看起来完整”而生成一个和真实产品不一致的产品图。

## 设计反馈问题

每轮生成后只问三个问题：

1. 你第一眼看到页面的五秒感受是什么？
2. 它像不像你的产品和品牌？
3. 有什么地方感觉不对、缺少或多余？

不要问“你喜欢吗”，因为得到的通常只是是/否，没有可执行信息。

## 引导用户给出有效反馈

开发者可能用 CSS 语言提反馈。要把它翻译成设计意图。

| 用户说 | 可能真正的问题 | 追问 |
|---|---|---|
| 不喜欢 | 整体不匹配 | 是颜色、布局还是气质？ |
| 无聊 | 视觉能量不足 | 要更强对比、更大标题还是更有变化的布局？ |
| 太满 | 信息层级不清 | 哪个区域最拥挤？ |
| 像模板 | 产品特异性不足 | 换结构、换字体、换图像策略，哪一项最需要变？ |
| 太营销 | 信息密度不足 | 减少装饰，增加具体信息？ |
| 颜色不对 | 色彩策略错误 | 太亮、太灰，还是色相不对？ |
| 产品被挡住 | 构图失败 | 先移动文案或遮罩，不要先改产品图 |
| Logo 模糊 | 素材被放大 | 检查源尺寸和显示尺寸 |
| 奖项被裁切 | 证据不完整 | 改用自然比例完整展示 |
| 布局好但颜色不对 | 局部认可 | 只改配色，保留布局 |
| 回到上一版 | 版本问题 | 从版本目录恢复 |

## 设计维度提示

展示页面时帮助用户关注：

- 信息清晰度：五秒内能否知道产品是什么？
- CTA 可见性：主按钮是否容易找到？
- 颜色感受：是否符合三个品牌形容词？
- 阅读顺序：从上到下是否合理？
- 可信度：是否像一个真实、被维护的品牌？
- 产品可见性：主体有没有被文字、卡片或装饰遮住？

## 推动确认

- 正向但不明确：问“还差哪一个最重要的改动，才能确认？”
- 从多个方向中选中：问“保留这个方向，还是继续微调？”
- 三轮细修后：问“继续完善，还是先固化这一版？”
- 五轮之后：问“现在最重要的一个改动是什么？”

## 反馈优先级

1. **必须修**：产品说不清、CTA 找不到、内容错误
2. **应该修**：品牌不匹配、板块顺序错误、产品被遮挡
3. **可选**：字体粗细、具体像素、微小间距

先解决第一层，再进入第二层，最后处理第三层。不要让用户在没有解决结构问题时无限纠结小细节。
